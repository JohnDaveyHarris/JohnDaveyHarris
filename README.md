### 🛠️ Мой инженерный подход

**Я выбираю инструменты под задачу, а не под тренды.** Вот что я умею и когда это применяю:

- ⚛️ **React 18+**  
  Хуки, композиция, порталы, Suspense. Контролирую ререндеры через мемоизацию. Понимаю, когда Concurrent Mode реально нужен, а когда — избыточен.

- 📦 **State Management**  
  Для серверного стейта — **RTK Query / TanStack Query** (кеширование, инвалидация, optimistic updates).  
  Для локального/форм — **RTK**, **Zustand** или контекст. Выбираю по объёму проекта и команде.

- 🚀 **Оптимизация**  
  На практике:  
  - Сократил бандл на **17%** через code splitting  
  - Поднял Lighthouse Performance с **55 → 86**  
  - Оптимизировал API: кеширование на бэке → ускорил ответ API на типовые запросы в **10+ раз**

- 🌐 **Работа с сетью**  
  Знаю, как строить надёжные клиент-серверные взаимодействия: ретраи, таймауты, отмена запросов, кеширование и инвалидация. Использую optimistic updates для улучшения UX.

- 🧩 **Архитектура**  
  Работаю с **FSD** и **Atomic Design**. Знаю, когда модульность оправдана, а когда — усложняет. Строю проекты так, чтобы их можно было масштабировать без боли.

- 🔄 **Fullstack-мышление**  
  Понимаю, как данные идут от БД → бэкенд → фронтенд. Это помогает проектировать API, с которым удобно работать на клиенте.
